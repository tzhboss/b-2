## Native protocol audit: exposed evaluation and limits

Source evidence:

- `processor.py:410-424` expects **train.jsonl, dev.jsonl, test.jsonl**. HF uses edit_train/edit_test names. The adapter stages a separate copy view with **train ← edit_train; dev ← edit_test; test ← edit_test**, records hashes and makes that reuse explicit. No change to downloaded source data.
- `data_module.py:300-310` creates train, dev and locality memory; **no test dataset**. `BaseKEModule:359-377` has train/val loaders, **drop_last=True**, batch size edit_num. No test_step/test_dataloader implementation on KGEditor.
- `models/KGEditor/run.py:91-109` checkpoints on **Eval/hits3 from validation**, then calls fit; final test call is commented. Consequently edit_test participates in model selection during every validation epoch, including native Lightning sanity validation. Final best-checkpoint evaluation on the same file must be called **native exposed evaluation**.
- With edit_num=2, FB final eval is **3086/3087 edits**, excluding zero-based row 3086 through native drop_last. WN evaluates all 830. Train uses 3086/3087 FB and 1490/1491 WN examples per epoch, with shuffled dropped example changing. No batch-size or drop-last repair.
- `DataCollatorForKE:157-164` prepends **8 locality probes** per edit batch, drawn by worker-local fixed permutation/cursor. No explicit wrap/reset in the collator. Worker process recreation normally supplies reset via loader lifecycle, not via an algorithmic reset. Locality probes can repeat across workers and edit batches; the exported count is **batch exposures, not a unique full-L-Test sweep**.
- User-authorized worker count **4 replaces author launcher's 32**. All mathematical/training flags retained, but because collator cursors are worker-local, this runtime change can change actual locality exposure weighting. It should be recorded alongside article comparison, not claimed numerically identical to 32 workers.
- `models.py:461-493,637-662`: actual optimizer is **RMSprop(centered=True)** on editor and alpha parameters; scheduler 1000 warmup / 200000 total steps; training uses absolute value of the constrained objective. Parser default optimizer=AdamW is not the implemented optimizer. Keep source behavior.
- `models.py:495-528`: ranks sort **all entity logits**, unfiltered, using PyTorch's default sort tie behavior. No KG filtered-ranking replacement, no deterministic tie repair, no relation-specific candidate restriction.
- `models.py:535-576` logs locality Hits@k. v8 Eq. (3) defines **RK@3 as count(after rank≤3)/count(before rank≤3)**. These equal locality Hits@3 only if every sampled baseline probe is rank≤3. Adapter exports baseline ranks and both quantities; do not silently equate them.
- v8 Eq. (4): **ER_roc = abs(mean_rank_after - mean_rank_before)/mean_rank_before; RK_roc = abs(locality_mean_after - locality_mean_before)/locality_mean_after**. These are rank rate-of-change metrics, **not ROC AUC**. Native launcher does not calculate them; observations calculate precisely these stated formulas for the sampled batch exposures.
- Native `valid_flipped` object exists but is not logged into checkpoint metrics; author filename template retains it. No numerical use of an invented valid_flipped statistic.

Adapter builds a vocab-only base-tokenizer view from the pinned HF vocab, retaining uncased standard BERT token settings, then lets native code add entity and relation tokens.
