# 056准备阶段优化

本地代码对应远程 `/data/lc/untzh/signals56_prepare_optimization_20261013`。

数据集本身固定。这里的准备不是重新生成图谱，而是为保护损失构造训练输入：

1. 读取旧/新TRAIN与已有模型，建立TRAIN真值、实体度数及关系角色结构。
2. 固定种子排列旧Top10合格答案，安排740步，每步32个保护答案。
3. 每个唯一旧查询抽取最多256个旧候选评分，确定分数尺度。
4. 排除已知正确答案，为合法新增候选构造随机和结构匹配旧参照，各4次。
5. 在冻结旧模型上将参照分数聚合为每答案标量，保存查询向量、旧答案分数、尺度、候选mask及两类参照摘要。

初始学习正例与负例序列复用052已保存tape，本次不重新生成。随机过程使用固定种子和查询身份，固定输入产生相同选择。不同gold的参照摘要必须分别保留。

## 已定位耗时

056真实准备1349.466秒，其中参照匹配1320.241秒、尺度14.737秒、分数聚合9.100秒、缓存写入4.433秒。四臂训练各4.394至7.458秒；这些训练计时已经复用准备结果和历史学习tape，不能当端到端成本。

优化使用固定结构分组、复用种子编码、单候选池直接填值，并保留原有随机抽样输出。`reference_adapter.py`保存对照实现，`fast_adapter.py`为优化实现。原056结果不改动。

真实319个保护答案的所有候选、参照ID、顺序、尺度抽样和匹配级别完全一致。完整740批准备585.799秒（9.76分钟），原1349.466秒（22.49分钟），本次异时计时加速2.304倍、耗时降低56.59%。740批共4440个缓存数组与原056逐元素完全相同。完整新准备分项：尺度14.712秒、参照匹配556.862秒、分数聚合8.562秒、磁盘写入4.498秒。没有重训、读取VALID/TEST或更改保护公式，不能把异时准备加速当独立部署速度研究。

首版预分组与第二版跳过单候选RNG分别只得到约1.03/1.54倍真实cohort速度，未完成完整准备；其源码、计时与部分cache留在远程`retained-v1`/`retained-v2`。最终版本增加分组数组与随机身份JSON编码复用，319个cohort速度2.802倍；完整准备加速以2.304倍为准。

## 哪些可以复用

同一TRAIN、固定旧模型参数、保护资格、抽样规则和种子下，结构、保护序列、尺度与参照摘要可以共用。改变保护系数或比较同一套输入下的保护公式无需重建。换快照或旧模型参数时，须更新受影响部分。单独运行绝对压分不需要计算随机/结构旧参照。

复用必须记录来源和原准备成本，不能把历史准备工作记为零成本。这里的工程加速不构成新保护算法的科学收益。

`run_with_prepared.py --output /data/lc/untzh/<新的实验目录>`是相同056设定的复用入口。它读取本目录的现成准备缓存，检查输入文件路径、大小、修改时间及准备参数是否仍相同；保留原准备成本记录，然后执行校准、训练和评价。它不自动重跑已完成056。更改数据、旧模型、种子或准备规则时不能沿用这份缓存。

本目录代码不设固定运行时长上限；只保留数值错误检查及阶段进度。
